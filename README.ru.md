# Domain OS

[![Tests](https://github.com/6kane1/DomainOS/actions/workflows/tests.yml/badge.svg?branch=main)](https://github.com/6kane1/DomainOS/actions/workflows/tests.yml)

[English](README.md) | **Русский**

Плейбук для [AME Wizard](https://ameliorated.io), который готовит **Windows 11 25H2 и 26H2 (сборки 26200, 26300), только Pro**, к играм. На Home и других редакциях установка останавливается на первом шаге, до любых изменений.

> **25H2 и 26H2 с версии 2.1.0.** 24H2 больше не поддерживается: у неё закончились обновления безопасности. «Держать Windows на 26H2» удерживает систему на 26H2 (поддержка до октября 2028) — ПК на 25H2 сначала получает обновление до 26H2.

**Короткий список изменений, каждое объяснено и проверяемо.** У каждого пункта ниже указан ключ реестра, служба или параметр, который он меняет.

> **Перед началом**
> - **Его можно отменить без переустановки Windows** (см. [Откат](#откат)). Удалённые приложения автоматически не возвращаются: откат перечисляет их, чтобы вы поставили нужные из Microsoft Store (сам Store, если был удалён, возвращается автоматически). Всё равно сначала попробуйте в виртуальной машине.
> - **Средний FPS от плейбука не растёт.** Вы получаете меньше фоновых процессов, отсутствие рекламы и принудительных перезагрузок и систему, настроенную одинаково каждый раз.
> - Domain OS — молодой проект. Версия 2.2.4 прошла тестировщиков и автоматическую проверку каждого изменения, но реальные ПК разные: сообщайте о том, что ломается.

## Что остаётся нетронутым — намеренно

| Компонент | Почему остаётся |
|---|---|
| Microsoft Defender, SmartScreen, «Безопасность Windows» | Без них ПК не защищён, а античиты перестают работать. |
| Secure Boot, TPM, VBS, целостность памяти, защитные механизмы ядра | Их проверяют FACEIT, Vanguard, EasyAntiCheat и BattlEye. |
| Обновления безопасности и качества, базы Defender | Система без них становится небезопасной за несколько недель. |
| Xbox Identity Provider, Gaming Services, приложение Game Bar | Через них игры входят в учётную запись и сохраняются. Оверлей Game Bar выключен, но приложение не удаляется. |
| Microsoft Store, App Installer (winget), Edge, WebView2 | Нужны лаунчерам и многим программам. Store можно убрать опцией «Maximum». |
| Основные службы Windows | Отключаются только службы, бесполезные на игровом ПК, каждая названа и объяснена. Массовое отключение вслепую ломает функции. |

## Поддерживаемые версии Windows

| Версия | Сборка | Обновления безопасности от Microsoft (Pro) |
|---|---|---|
| 26H2 | 26300 | до октября 2028 |
| 25H2 | 26200 | до октября 2027 |
| 24H2 | 26100 | закончились в октябре 2026 — **не поддерживается** с 2.1.0 |

Даты взяты со [страницы жизненного цикла Microsoft](https://learn.microsoft.com/lifecycle/products/windows-11-home-and-pro). Плейбук не отключает обновления безопасности ни на одной версии. AME Wizard не запустит его на сборках, кроме 26200 и 26300.

Плейбук запускался на 25H2 и 26H2. На 25H2 Windows предложит обновление до 26H2: это обычное обновление, плейбук оно не ломает.

## Что меняет Domain OS

Каждый пункт находится в `playbook/Configuration/Tasks/*.yml` с комментарием рядом.

### Встроенные приложения (опция, включена)
Удаляются приложения с рекламой или фоновым запуском: Clipchamp, Новости, Погода, поиск Bing, Solitaire, Teams, приложение Copilot, новый Outlook, Dev Home, Feedback Hub, «Техническая поддержка», «Советы», хаб Microsoft 365, Power Automate, To Do, «Кино и ТВ», Cortana, Карты, старая Почта, Family, «Связь с телефоном», «Мобильные устройства» (Cross Device), Виджеты и рекламные заглушки (Disney+, LinkedIn). Spotify не удаляется (его ставят сами; реклама Spotify в «Пуске» и так убирается вместе с чистыми значками «Пуска»). Windows запрещено возвращать Dev Home и Outlook и молча ставить «рекомендуемые» приложения.

- **OneDrive** (опция, включена): удаляется собственным деинсталлятором. Файлы остаются.
- **Maximum** (опция, выключена): дополнительно Store, приложение Xbox, Фотографии, Камера, Запись голоса, Часы, Записки.

### Приватность и реклама
- Диагностические данные на обязательном уровне; служба телеметрии и её помощник отключены.
- Отключён плановый сбор данных, включая оценку совместимости, известную долгими всплесками нагрузки на диск и процессор, и её второе задание `MareBackup`.
- Сеансы трассировки телеметрии (`Diagtrack-Listener`, `SQMLogger`) больше не запускаются при загрузке: после отключения службы их события никто не читал.
- Включены политики «Отключить телеметрию приложений» и «Отключить сборщик инвентаризации». Механизм совместимости старых игр не тронут.
- Все остальные документированные политики диагностических данных, которые работают на Pro: без запросов отзывов, без имени устройства в данных, без сбора дополнительных журналов и дампов, без загрузки OneSettings, без уведомления о смене уровня; CEIP, средство записи действий, отчёты об ошибках Windows и отчёты MRT о заражениях выключены; без обучения на наборе текста и рукописном вводе, без онлайн-распознавания речи, без передачи рукописных данных; необязательные диагностические данные Edge выключены (Edge, как при любой политике, покажет «управляется вашей организацией»).
- Выключены рекламный идентификатор, персонализированные предложения, запросы отзывов, журнал действий и Recall.
- Выключены предложения и реклама в «Пуске», «Параметрах», на экране блокировки и в уведомлениях.
- Поиск в «Пуске» больше не отправляет набранное в Bing. Панель виджетов выключена.

### Службы и фоновая работа
- **Базовый набор (опция, включена):** шесть заданий по расписанию от удалённых приложений и сбора данных (карты, семейная безопасность, прокси проверки диска, SQM). Edge остаётся, но больше не держит процессы после закрытия окна. Сами службы остаются такими, как их настраивает Windows (одно исключение: раз приложение «Карты» удалено, служба «Диспетчер скачанных карт» запускается по запросу, а не при каждой загрузке, где она только завершалась с ошибкой): печать, Bluetooth, факс, диагностика, синхронизация и мелкие системные драйверы не трогаются.
- **На ваш выбор (опции, выключены):** индексирование файлов, гибернация с быстрым запуском, фоновая работа приложений из Store. Каждая из них отнимает функцию, поэтому каждая — отдельной галочкой.
- **Службы и задачи телеметрии (применяется всегда):** отчёты об ошибках (WerSvc), помощник совместимости (PcaSvc), телеметрия (DiagTrack), хост AI-компонентов Windows (WSAIFabricSvc), сборщик сведений о совместимости (InventorySvc); служба отслеживания изменившихся связей (TrkWks) остаётся как в Windows — «Автоматически» (версии 1.6.7–2.1.0 её удаляли; на таких ПК её регистрация возвращается из сохранённой копии и служба снова запускается); а также 14 заданий телеметрии: перепись устройств, отправка данных об использовании, телеметрия энергопотребления, проверка автозагрузки, сканирование неполадок, диагностика диска и питания, WinSAT, отправка отчётов об ошибках. Дефрагментация/TRIM, резервная копия реестра, точки восстановления, SysMain, синхронизация времени и Defender остаются. Версии 1.5.0–1.6.0 выключали больше (диагностику, синхронизацию, мелкие драйверы, печать, Bluetooth, базовые службы, политику перезагрузки); установка 1.6.0 или новее возвращает всё это к значениям, которые были до первой установки.
- **Тип запуска гипервизора:** версии 1.5.7–1.6.0 выключали запуск гипервизора, если виртуализация в BIOS была выключена. Этого шага больше нет (если потом включить виртуализацию, целостность памяти и VBS молча не запустились бы); установка 1.6.2 или новее возвращает прежнее значение.
- Что это даёт: меньше процессов и занятой памяти после загрузки — это видно в диспетчере задач. Само по себе FPS это не повышает.
- Никогда не отключаются: Defender, Центр обновления, звук, сеть, ввод, планировщик, WMI, службы Xbox, службы TPM и Secure Boot, службы античитов.

### Центр обновления Windows (две опции, включены)
- **Держать Windows на 26H2 (без дальнейших крупных обновлений)**: `TargetReleaseVersion` = 26H2. На 26H2 меняется только закрепление; на 25H2 это значит одно крупное обновление до 26H2 (небольшой пакет включения и одна перезагрузка), а дальше крупных обновлений нет. **26H2 получает обновления безопасности до октября 2028:** до этого срока примените более новую версию Domain OS (она передвинет закрепление) или запустите «Give Windows Update back its defaults» из папки «Domain OS» в меню «Пуск».
- **Без драйверов из Центра обновления:** драйверы производителей вы ставите сами; инструкция покажет какие.

Обновления безопасности продолжают приходить. В папке «Domain OS» в меню «Пуск» есть ярлык, который возвращает всё как было.

### Игровые настройки
- **Запись игр выключена полностью:** фоновая запись (Game DVR), запись вручную, звук, курсор и микрофон в записи, плюс политика, запрещающая запись и трансляции. В Windows 11 фоновая запись по умолчанию выключена; если она была включена, то отнимала время видеокарты и диска в каждой игре — теперь она выключена, пока вы снова не разрешите запись.
- **Ускорение указателя выключено.**
- **Сочетания залипания, фильтрации и озвучивания клавиш выключены** — пять нажатий Shift больше не выбрасывают окно поверх игры.
- **Game Bar выключен (с 1.6.8).** Не открывается по Win+G и кнопке Xbox на геймпаде, но само приложение остаётся: его можно включить в Параметры → Игры. Откат возвращает прежние значения.
- **Xbox mode выключен (с 1.6.8):** полноэкранный режим Xbox (Параметры → Игры → Xbox mode) не используется как домашний экран. Само приложение Xbox остаётся. Откат возвращает прежнее значение.
- **Игровой режим остаётся включённым**, как в Windows по умолчанию: драйвер AMD 3D V-Cache на Ryzen X3D с двумя CCD по нему держит игры на CCD с кэшем, а ещё он не даёт Центру обновления ставить драйверы и просить перезагрузку во время игры.
- **Аппаратное ускорение планирования GPU (HAGS), включено по умолчанию (опция):** `HwSchMode` = 2 в `HKLM\SYSTEM\CurrentControlSet\Control\GraphicsDrivers`. Видеокарта сама распределяет свою работу, это снимает часть работы с процессора и задержку при отправке кадров. Нужны поддерживаемые видеокарта и драйвер (NVIDIA GTX 10 и новее, AMD RX 5000 и новее, Intel Arc), иначе Windows значение игнорирует. Работает после перезагрузки; откат возвращает прежнее значение.
- **`Win32PrioritySeparation` = 0x18:** длинные фиксированные кванты времени, одинаковые для активной программы и фоновых (стандартное значение Windows даёт короткие переменные кванты, у активной программы в 3 раза длиннее). Почему 0x18: замеры Zero Unflesh показали, что лучшая комбинация — 0x18 **вместе с включённым игровым режимом**, и Domain OS ставит именно её (игровой режим остаётся включённым). Наш собственный A/B-тест от 19.11.2026 (один ПК, CS2 на пустой карте, одна точка, варианты чередовались) не нашёл измеримой разницы между 0x18 и стандартным 0x26: FPS, 1% / 0.1% low и время кадра — в пределах разброса между прогонами. Поэтому 0x18 остаётся на основании тех замеров; прогоны с других ПК на странице результатов приветствуются. Откат возвращает прежнее значение.

### Интерфейс
Показываются расширения файлов, проводник открывается на «Этот компьютер». Влияния на производительность не заявляется.

- **Чистая панель задач** (опция, включена): все закреплённые программы откреплены, кнопки поиска, представления задач и чата скрыты — остаётся только кнопка «Пуск» (и программы, пока они запущены). Исходные закрепления сохраняются, откат их возвращает. Панель очищается только при первой установке: если новая версия ставится поверх старой, закреплённые с тех пор программы остаются. Без этой опции поиск становится значком.
- **Закрепления в «Пуске»** (вместе с удалением встроенных приложений): список закреплённых собирается заново из установленных программ — Параметры, Проводник, Edge, Domain OS Toolbox, а также Store, Xbox, Терминал и Блокнот, если они есть, — поэтому плитки удалённых приложений (Copilot, Teams, Outlook, Solitaire, папка «Другое») исчезают. Используется политика `ConfigureStartPins` с `applyOnce` (Windows 11 24H2 с KB5062660 и новее): «Пуск» заменяет список закреплённых при следующем входе и больше никогда, поэтому закрепления можно менять как обычно. На старых сборках одноразовая задача снимает политику после того, как она сработала. Только при первой установке; откат возвращает исходные закрепления.

- **Тёмная тема** (опция, включена): для Windows и приложений.
- **Уведомления выключены** (опция, с 2.1.1 по умолчанию не отмечена): главный переключатель в «Параметры → Система → Уведомления». Никаких всплывающих окон и звуков поверх игры. Defender продолжает работать, его состояние видно в «Безопасности Windows». Уведомления можно включить в «Параметрах» в любой момент.
- **Права администратора без запроса UAC** (опция, по умолчанию выключена с 2.1.9): ваша учётная запись и так была администратором; теперь программа, которой нужны права администратора, получает их без окна «Разрешить этому приложению вносить изменения?». Сам UAC остаётся включённым, поэтому приложения Store, Xbox и античиты работают. Цена: любая запущенная программа, которая просит права, получает их молча, поэтому запускайте только то, чему доверяете. По умолчанию выключено: ставьте галочку, только если нужно удобство; откат возвращает окно.

### План питания (опция, включена)
**Domain OS** — свежая копия плана Windows «Сбалансированный», в которой изменены четыре параметра при питании от сети и больше ничего. Параметры процессора, парковка ядер и буст остаются как в «Сбалансированном» — под него AMD и Intel настраивают свои процессоры; от батареи ноутбук работает как со «Сбалансированным».

| Параметр | Значение | Что делает |
|---|---|---|
| Выборочная приостановка USB | выкл. | USB-хабы, мышь, клавиатура, гарнитура и USB-звук не засыпают. |
| Управление питанием канала PCI Express (ASPM) | выкл. | Видеокарта, NVMe и сетевая карта не уводят линию PCIe в энергосбережение. |
| Отключать дисплей через | никогда | Удобство (экран не гаснет на долгих загрузках и при просмотре видео), а не производительность. На OLED-мониторе, возможно, стоит задать время: Параметры → Система → Питание. |
| Отключать диск через | никогда | |

Прежний активный план запоминается; откат снова делает его активным и удаляет этот. Установка 1.6.0 поверх старой версии собирает план заново из «Сбалансированного», так что параметры процессора прежнего плана «Domain OS Low Latency» уходят.

### Инструменты
- **DomainScheduler** (опция, включена): ставится в `Program Files\Domain OS` и запускается с Windows для каждого пользователя. Расставляет потоки игры и понижает фоновые программы, пока вы играете.
- **Библиотеки** (опция, включена): Visual C++ 2015–2022 x64 и x86, DirectX June 2010, 7-Zip — скачиваются у производителей; файлы Microsoft принимаются только с действительной подписью Microsoft, а 7-Zip (у него нет подписи) — только одна известная версия, SHA-256 которой совпадает со значением в `Install-Runtimes.ps1`.
- **Инструкция по драйверам** (опция, включена): после перезагрузки открывается страница (с обычными правами вашей учётной записи, не от администратора), составленная для вашего ПК: какие драйверы ставить, в каком порядке, со ссылками на официальные страницы, и как поставить драйвер NVIDIA без лишнего через NVCleanstall. Она же проверяет частоту обновления монитора и работает ли память на заявленной частоте.
- **Обои** (опция, включена): картинки Domain OS копируются в `C:\Windows\Web\Wallpaper\Domain OS`. На рабочем столе — слайд-шоу из них (новая картинка каждые 10 минут, в случайном порядке), на экране блокировки — одна из них. В «Параметры → Персонализация → Темы» появляется тема «Domain OS», чтобы вернуть слайд-шоу позже. Включить слайд-шоу на экране блокировки программно Windows не позволяет, поэтому: «Параметры → Персонализация → Экран блокировки → Слайд-шоу → Обзор → `C:\Windows\Web\Wallpaper\Domain OS`». Это обычные настройки, ничего не блокируется; откат возвращает прежние обои рабочего стола и экрана блокировки. Копия ваших прежних обоев хранится в `%ProgramData%\Domain OS\Undo\Wallpaper\<учётная запись>`, читать её могут только эта учётная запись и администраторы. При установке поверх 1.4.0–2.1.0 (они сами ставили картинку Domain OS) исходные обои берутся из состояния, которое эти версии сохранили до первого изменения; если того файла уже нет, откат ставит стандартные обои Windows.
- **Ярлык:** «Domain OS Toolbox» на рабочем столе и в меню «Пуск».
- **Check Domain OS** (всегда): Пуск → Domain OS → Check Domain OS. См. [Проверка](#проверка).

## Откат

Domain OS меняет настройки, а не вырезает компоненты Windows. Поэтому его можно вернуть.

- **Перед первым изменением** плейбук записывает текущее состояние каждого значения реестра, службы и задания, которые может затронуть (`%ProgramData%\Domain OS\Undo\state.json`, плюс вторая копия исходного состояния `state.original.json`, которая пишется один раз и больше не меняется). Если состояние не удаётся сохранить или сохранённое повреждено, установка **останавливается до любых изменений** и оставляет файл как есть.
- **Следом ставится Undo Domain OS**, тоже до любых изменений, — он есть в меню «Пуск», даже если установка остановится на середине.
- **Пуск → Domain OS → Undo Domain OS** возвращает это состояние: реестр, типы запуска служб, задания планировщика, гибернацию, OneDrive, план питания, значки панели задач и «Пуска», обои, и удаляет запись выбранных опций (`HKLM\SOFTWARE\Domain OS\Options`). После этого перезагрузитесь. Если что-то вернуть не удалось, это видно в журнале, сохранённое состояние остаётся, и после перезагрузки откат запускают ещё раз. Службы и задания, которые Windows не даёт менять администраторам (они принадлежат TrustedInstaller или SYSTEM), возвращает разовый шаг от имени SYSTEM, который сразу после этого удаляется.
- **Удалённые приложения** автоматически не возвращаются: скрипт перечисляет их, переустанавливает Microsoft Store, если он был удалён, а нужные вы ставите из Store сами.
- Запуск с `-WhatIf` показывает, что будет сделано (и когда скрипт сначала просит права администратора), а с `-RemoveTools` заодно убирает программу Domain OS (сначала выполняется её собственный полный сброс, потом возвращаются значения плейбука).
- **Сохранённое состояние защищено:** `%ProgramData%\Domain OS` могут менять только администраторы (наследование выключено; SYSTEM и Администраторы — полный доступ, Пользователи — только чтение). Откат и установщик берут сохранённый файл, только если его владелец SYSTEM, Администраторы, TrustedInstaller или учётная запись администратора (обычная учётная запись подложить файл не может; файлы, которые старые версии сохранили под вашей учётной записью администратора, передаются группе «Администраторы»), восстанавливают только те значения реестра, службы и задания, которые могут затронуть файлы задач плейбука, а сохранённые `.reg` читают по одному значению, а не импортируют целиком.

**Настройки пользователя и несколько учётных записей.** AME Wizard записывает пользовательские (HKCU) настройки плейбука **во все учётные записи на ПК и в профиль по умолчанию для учётных записей, созданных позже**. Сохранённое состояние и откат охватывают **только ту учётную запись, от которой запущен откат**: у остальных учётных записей пользовательские настройки Domain OS остаются (ускорение указателя, тёмная тема, кнопки панели задач, рекомендации и прочее) — их меняют в Параметрах там. Значки панели задач и «Пуска» и обои меняются только у учётной записи, от которой шла установка, и откат возвращает их, когда его запускает она.

**Что откат не возвращает:**
- OneDrive для учётных записей, созданных позже (запись первого входа в профиле по умолчанию остаётся удалённой; OneDrive можно поставить с microsoft.com или из Store);
- записи Центра обновления о повторной установке Dev Home, Cross Device и нового Outlook (`Orchestrator\UScheduler_Oobe`; Windows запишет их снова со следующим крупным обновлением);
- установленные библиотеки (Visual C++, DirectX, 7-Zip) — они остаются; при желании удалите их в Параметры → Приложения;
- картинки Domain OS в `C:\Windows\Web\Wallpaper\Domain OS` и пользовательские настройки других учётных записей (см. выше).

## Остановка при ошибке

Установка **останавливается при первой ошибке** в собственных шагах: каждый шаг, который запускает скрипт Domain OS, останавливает AME Wizard, если скрипт завершился с ошибкой, а причина записывается в `%ProgramData%\Domain OS\Logs\install.log` (строка с `FAILED`). Без ошибки скрипт завершается, если сделал своё или делать было нечего. Одно исключение: библиотеки (Visual C++, DirectX, 7-Zip) скачиваются у производителей, поэтому сбой сервера или связи попадает только в `runtimes.log`; поставить их ещё раз можно в любой момент: Пуск → Domain OS → Install runtimes.

Собственные действия Windows (значения реестра, службы, задания планировщика, приложения) просто останавливать при ошибке нельзя: служба или задание, которых нет в этой сборке Windows, останавливали бы любую установку. Вместо этого **последний шаг проверяет всё**: `Check-DomainOS.ps1 -AfterInstall` сравнивает ПК со списком всех изменений (`expected.json`, он строится из файлов задач при сборке плейбука) для выбранных вами опций. Служба, задание или приложение, которых в этой сборке нет, пропускаются; любое значение или состояние, которое отличается, останавливает установку с ошибкой. Каждое расхождение — одна строка в `%ProgramData%\Domain OS\Logs\check.log`: что, что ожидалось, что найдено, и файл задач со строкой, где это задаётся.

Состояние для отката сохраняется до первого изменения, так что остановленную установку всегда можно вернуть через Undo Domain OS.

Выбранные опции записываются в `HKLM\SOFTWARE\Domain OS\Options` (одно значение на опцию). Это собственная запись Domain OS, а не настройка Windows: в сохранённое состояние она не входит, и откат удаляет её после полного отката.

## Проверка

**Пуск → Domain OS → Check Domain OS** проверяет ПК в любой момент. Проверка только читает: она никогда не меняет ни настройку, ни службу, ни задание, ни приложение, ни файл (пишет только свой отчёт). Она просит права администратора, показывает PASS / WARN / FAIL на экране и сохраняет полный отчёт на рабочий стол (`Domain OS check <дата>.txt`) — этот файл и присылайте, когда просите помощи.

Что проверяется:
- **каждое изменение плейбука** для опций, записанных при установке, как в конце установки (в другой учётной записи — пользовательские настройки той записи, от которой запущена проверка);
- **готовность отката**: защита папки данных (владелец, права, никаких ссылок), сохранённое состояние (`state.json`, `state.original.json`), инструменты отката и его список разрешённого (он должен покрывать каждое изменение), и **пробный запуск отката** (`-WhatIf`), который должен пройти без сбоев;
- задания планировщика Domain OS (обычные права, без окна), автозапуск Toolbox и его версия, последняя применённая версия, строки `FAILED` последней установки, ошибки программ Domain OS в журналах событий;
- **здоровье Windows**: `DISM /CheckHealth` и `sfc /verifyonly` (только чтение; вместе могут идти несколько минут; `-Quick` их пропускает), устройства с проблемой драйвера, ожидающая перезагрузка, Центр обновления (служба, последний успешный поиск и установка), состояние дисков, неожиданные выключения и синие экраны за 7 дней, самые частые ошибки в журналах событий за 24 часа, свободное место на системном диске. К каждому WARN и FAIL — совет простыми словами.

FAIL в части Domain OS значит, что что-то не так, как поставил Domain OS: обычно это изменила другая программа или обновление Windows, или вы сами в Параметрах. Повторное применение плейбука это исправит; откат по-прежнему возвращает исходное состояние.

### Попробовать версию, вернуться, поставить новую
1. Примените версию. Её номер и дата записываются в `%ProgramData%\Domain OS\history.log`.
2. Если не понравилось: **Undo Domain OS**, перезагрузка. Windows такая же, как до плейбука; сохранённое состояние израсходовано (если откат сообщил об ошибке, оно остаётся — запустите откат ещё раз).
3. Примените новую версию как в первый раз: перед первым изменением она сохранит свежее состояние.

Новую версию можно применить и **поверх** старой без отката: исходное состояние сохраняется, а то, что новая версия затрагивает дополнительно, добавляется к нему — один откат по-прежнему вернёт всё.

## Рассмотрено и не включено

| Изменение | Почему его нет |
|---|---|
| Разрешение таймера, параметры тиков `bcdedit` | С Windows 10 2004 запрос таймера действует на процесс; воспроизводимого выигрыша нет. |
| MMCSS / `SystemResponsiveness` / `NetworkThrottlingIndex` | Влияют только на потоки мультимедийного класса; воспроизводимого выигрыша в играх нет. |
| Отключение поиска | Ломает поиск файлов; сэкономленная память не видна во времени кадра. (SysMain всегда остаётся включённым.) |
| Отключение состояний простоя процессора (`IDLEDISABLE`), пороги и интервалы производительности | Отключение простоя повышает температуру и отнимает запас для буста; пороги игнорируются процессорами с аппаратным управлением частотой (Intel HWP, AMD CPPC). |
| Отключение ~40 сеансов ETW и ~120 плановых заданий | Задания работают в окне обслуживания, когда ПК простаивает; в игре они не выполняются. Отключены только сеансы службы, которую мы сами выключили. |
| Отключение `Ndu`, `DPS` | Механизм есть (`Ndu` стоит на сетевом пути), но замеров нет. Появится, когда будет трасса WPA с цифрами. |
| `SvcHostSplitThresholdInKB` | Экономит 100–200 МБ памяти, процессор не разгружает, службы теряют изоляцию друг от друга. |
| Десятки недокументированных значений в `Control\Power` и `Session Manager\kernel` | Нет подтверждения, что актуальные сборки их вообще читают. |
| Отключение полноэкранных оптимизаций | Нет воспроизводимого выигрыша; оптимизации нужны для режима flip и VRR. |
| Отключение защитных механизмов, VBS, Defender | На части систем измеримо, но ценой безопасности и поддержки античитов. Не предлагается. |

Если вы можете показать измеренное, повторяемое улучшение для чего-то из этого списка — откройте issue с цифрами.

## Ранние версии: что они делали и как это вернули

Domain OS не всегда был таким аккуратным, как сейчас. Всё перечисленное ниже убрано, а на ПК, где это стояло, прежние значения возвращаются сами.

| Версии | Что делали | Сейчас |
|---|---|---|
| Toolbox 1.6–1.11 | Необязательные переключатели «тестового режима», менявшие защиту на скорость: выключение защиты памяти / VBS / гипервизора, обходов Spectre и Meltdown, стандартной защиты от эксплойтов, политик Defender и SmartScreen. По умолчанию выключены, включались только вручную. | Убраны в **1.12.0**. При каждом запуске и при сбросе к заводским настройкам возвращаются значения, сохранённые до их включения. |
| Тестовые сборки Toolbox (до 1.12.0) | Могли добавлять exe запущенной игры в исключения Defender на время игры. | Убрано. Toolbox только снимает исключения, оставленные такой сборкой (при каждом запуске и выходе), и никогда их не добавляет. |
| Плейбук до 1.5.8 | Выключал службы диагностики, синхронизации и фоновые службы, мелкие системные драйверы; печать и Bluetooth можно было выключить необязательными галочками. | Убрано в **1.5.9**; установка новой версии возвращает прежние значения из сохранённого состояния. |
| Плейбук 1.5.7–1.6.0 | Выключал запуск гипервизора, если виртуализация выключена в BIOS. | Убрано; этот шаг теперь восстанавливает запуск гипервизора (см. выше). |
| Плейбук 1.6.7–2.1.0 | Удалял службу отслеживания изменившихся связей (TrkWks). | 2.1.1 возвращает её и снова включает автоматический запуск. |
| Плейбук до 2.1.1 включительно (до вечера 18.11.2026) | Удалял Spotify из Microsoft Store вместе с рекламными заглушками и запрещал ему возвращаться. | Spotify больше не удаляется; запрет снимается при установке. |
| Плейбук до 2.1.1 включительно | В `%ProgramData%\Domain OS`, где хранится состояние для отката, не было собственных прав доступа; сбой сохранения состояния не останавливал установку; Undo ставился последним; инструкция по драйверам открывалась с правами администратора. | Папка получает собственные права (менять её могут только администраторы), существующая исправляется; сохранённые файлы используются, только если их записала учётная запись администратора или Windows; сбой сохранения останавливает установку до любых изменений; Undo ставится сразу после сохранения; инструкция открывается с обычными правами. |

С версии 2.0 правило такое: Defender, SmartScreen, VBS / защита памяти, TPM и Secure Boot не трогаются — ни плейбуком, ни Toolbox.

## Как пользоваться
1. Установите чистую Windows 11 Pro, 25H2 или 26H2. **До первого подключения к интернету** запустите `extras/No-WU-Drivers.reg`: иначе Windows Update поставит свои драйверы раньше, чем плейбук это запретит. Затем завершите обновления Windows и перезагрузитесь.
2. Скачайте AME Wizard и `Domain-OS-2.2.4.apbx`.
3. Перетащите `.apbx` в AME Wizard, выберите опции, запустите.
4. Перезагрузитесь. Откроется инструкция по драйверам: пройдите её сверху вниз.

AME Wizard сообщит, что плейбук не верифицирован: верификацию выдаёт команда AME, у проекта её пока нет.

## Сборка из исходников
`./build.sh` (нужны `7zr` и Python 3 с PyYAML): проверяет файлы задач и каждый скрипт PowerShell, записывает `playbook/Executables/expected.json` через `tools/gen-expected.py` (список всех изменений с файлом и строкой, с которым Check Domain OS сравнивает ПК; сборка также останавливается, если `Tasks/options.yml` записывает не ровно те опции, что есть в `playbook.conf`), затем упаковывает `playbook/` в архив 7z с паролем `malte`, как ожидает AME Wizard.

**Toolbox** тоже лежит в этом репозитории: в `toolbox/` — его полный исходник (C#, .NET 8, WPF) с тестами. Исходник идёт за разработкой, поэтому может быть новее выпущенного Toolbox; выпущенная программа — `DomainOS-Toolbox-1.15.0.exe` в [Releases](https://github.com/6kane1/DomainOS/releases).
- `./build.sh` — упаковывает exe, сохранённый как `toolbox/DomainScheduler.exe` (выпущенный; если его нет, плейбук собирается без программы);
- `./build.sh путь/к/DomainScheduler.exe` — упаковывает указанный exe;
- `./build.sh --toolbox-from-source` — сначала собирает Toolbox из `toolbox/src` (нужен .NET 8 SDK);
- тесты: `dotnet test toolbox/tests/DomainScheduler.Tests`.

**Доказательство, что exe Toolbox собран из этого исходника:** начиная с 1.15.0 Toolbox собирается на машинах самого GitHub workflow-ом `.github/workflows/toolbox-build.yml` (сначала тесты), и каждый exe получает подписанное подтверждение происхождения сборки. Проверить любую копию можно через GitHub CLI: `gh attestation verify DomainScheduler.exe -R 6kane1/DomainOS` — команда назовёт workflow и точный коммит; файл, изменённый хоть на один байт, проверку не пройдёт. (1.14.1 и тестовые сборки до 1.15.0 собраны до появления этой проверки.)

**Доказательство, что архив плейбука собран из этого исходника:** начиная с 2.2.4 `Domain-OS-<версия>.apbx` собирается workflow `.github/workflows/apbx-build.yml` на машинах GitHub: он берёт аттестованный exe Toolbox (и проверяет его аттестацию), прогоняет все тесты, упаковывает и аттестует архив. Проверка: `gh attestation verify Domain-OS-2.2.4.apbx -R 6kane1/DomainOS`. Архив шифруется со случайной солью, поэтому пересборка никогда не даёт тот же SHA-256: аттестация привязана к опубликованному файлу.

Скачанные файлы проверяются по SHA-256: `Get-FileHash .\Domain-OS-2.2.4.apbx` в PowerShell должен совпасть со значением на сайте и в описании релиза.
